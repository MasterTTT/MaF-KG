# 第一层语义图迭代记录 04

## 实验目标与控制变量

本轮针对第三节泛化较差的问题，先修复教材结构解析，再用第四节进行盲式泛化测试。核心问题不是追求单轮最高分，而是区分：

1. 可由代码确定修复的分块与证据错误；
2. DeepSeek Pro 随机采样造成的节点选择波动；
3. 当前第一层 schema 和 Gold 边界本身带来的争议；
4. 仍需下一轮实验验证的上游语义选择缺陷。

模型实验统一使用 `deepseek-v4-pro`、thinking enabled、reasoning effort medium、max tokens 24000，并通过 `--no-resume` 禁用本地断点读取。系统提示词哈希始终为 `4c299d71f6baaed80a04ef6cb40a8db9a634ade22aec2893343a7908e75d30c7`，本轮结构修复没有改提示词。

## Gold 口径

第三节使用 `evaluation/gold/semantic_first_three_sections_v2.json`。该版本采用原子语义口径：左/右极限、正/负无穷极限均为必抽 Concept；`ε-δ` 和 `ε-X` 论证法为可选 Method。

第四节 Gold 在首次模型调用前建立于 `evaluation/gold/semantic_fourth_section_v1.json`，包含 9 个必抽节点：

- Concept：无穷小、无穷大、正无穷大、负无穷大、铅直渐近线；
- Property：零是唯一的常数无穷小、无穷大函数不存在有限极限；
- Criterion：函数极限的无穷小表征；
- Result：无穷大与无穷小的倒数关系。

模型运行后只补充经过人工核验的等价表面名称，没有改变任何 M/O/X 标签或 Claim kind。关系 Gold 仍为 `pending`，因此不能报告关系 Precision、Recall 或 F1。

稳定问题如下：

1. 正无穷大和负无穷大在修复前后共六轮均未成为独立 Concept，而被吸收到“无穷大”描述中；
2. “无穷大函数不存在有限极限”六轮均未形成独立 Property；
3. “零是唯一常数无穷小”修复前后都只命中 `1/3`，结构修复没有提高观察频率；
4. 倒数关系各有 `2/3` 正确标为 result，另一次被错分为 property；
5. 修复后 r2 把“铅直渐近线”错误建模为 criterion Claim，而不是 Concept；
6. Concept 描述仍会吸收独立性质和辨析内容，例如“无穷大不是数”和“极限不存在”；
7. 所有第四节 MathExpression 均能在原始证据中逐字命中，但每轮只抽 2 至 3 个，覆盖不稳定。

第四节是有效的盲测失败案例：结构干净不等于语义泛化成功。当前模型在“一个总 Concept”与“可独立引用的子 Concept”、定义与 criterion、Concept 描述与独立 Property 之间仍不稳定。

## 核心结论

1. v1.5.2-v1.5.4 修复了三个真实、可复现的结构问题，证据角色和标题层级明显更可信；
2. 第三节 v1.5.2 三轮节点平均 F1 较高，但最终回归仍能降至 `.7647`，说明单轮稳定性不足；
3. 第四节盲测没有显示语义泛化改善，当前版本不能据此宣布第一层 schema 已稳定；
4. 当前 prompt payload 只发送 `teaching_block_ids`，没有发送每个 block 的 `discourse_role` 与行范围。因此 v1.5.3 的角色修复主要改善结果 provenance，模型并不知道 L13 已从 example 变为 paragraph。这解释了零常数性质命中频率没有改变；
5. 下一轮最值得单变量验证的改动，是向模型提供紧凑的 `{block_id, discourse_role, start_line, end_line}` 列表，并明确这些标签只是导航提示、正文仍是唯一证据；
6. 在关系 Gold 完成前，只能做逐边人工审查和跨轮 Jaccard，不能声称关系层达到某个 Precision/Recall/F1。
