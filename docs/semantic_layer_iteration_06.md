# 第一层语义图迭代记录 06

## 实验目标

本轮不直接设计可泛化分块模板，而是先验证“实际改变 chunk 边界”是否能够改善第一层语义抽取。实验使用 v1.5.6 的严格 `--experimental-chunk-spans` 参数，人工指定行区间；计划若重叠、遗漏非空正文、超出文档或切穿 teaching block，程序直接报错。

除 chunk 组成方式外，节点 schema、memory、Gold、模型与 Prompt 均保持不变。模型为 `deepseek-v4-pro`，thinking enabled，reasoning effort medium，max tokens 24000。Prompt 哈希仍为 `7c2b99ab03140944d1211289e08160992d0ebe2b481fbc9a80639203a2891007`。

本轮是筛选实验，每节只保留一个成功产物，不能据此报告稳定性或显著性。

## 实验分块

### 第四节

第四节从 2 块拆为 7 块：

- `L1-L7`：无穷小引入与定义；
- `L9-L12`：局部例题；
- `L13-L54`：零常数性质与函数极限的无穷小表征；
- `L55-L79`：无穷大定义；
- `L81-L111`：局部例题；
- `L112-L114`：铅直渐近线的一般化陈述；
- `L116-L151`：无穷大与无穷小的倒数关系定理。

### 第三节

第三节最初从 5 块拆为 8 块，隔离三组例题、单侧极限定义与无穷远定义。L256-L301 的性质群仍在一个块中，模型连续两次为 6 个 Claim 漏掉必填 `mention`，Pydantic 均按 schema 拒绝，没有自动补字段。

随后只进一步拆分 L256-L301，最终成功计划共 14 块：

- `L1-L9`、`L11-L55`；
- 例题专块 `L58-L149`；
- 单侧极限与判据 `L150-L170`；
- 例题专块 `L172-L199`；
- 无穷远定义 `L200-L227`；
- 例题专块 `L229-L255`；
- 性质标题与导语 `L256-L258`；
- 定理/推论分别为 `L260-L261`、`L262-L271`、`L272-L285`、`L286-L289`、`L290-L293`、`L294-L301`。

最终运行复用了同一 v1.5.6 指纹下前 7 块的检查点，仅重新生成新的性质块。没有读取 v1.5.5 或其他版本的抽取结果。

## 关系与表达式代价

节点提升没有同步扩展到全部图谱质量。

第三节 v1.5.6 有 20 条关系，但原角色版稳定出现的两条 `derived_from` 均消失。将每个定理拆成独立块后，模型虽然能通过 memory 连接各 Claim 到有限点函数极限，却没有恢复“加强形式/推论 derived_from 局部保号性”。说明过细切分会削弱同一性质群的局部逻辑上下文。

第三节 MathExpression 从角色版每轮 8 个降为 5 个，对照 v1.5.2 为每轮 11 个；第四节为 3 个。两节共 8 个表达式均逐字来自原文，保真没有下降，但覆盖明显收缩。

## 成本与失败

第四节 7 次成功请求，API latency 为 376.6 秒，total tokens 为 71,838；角色版平均为 197.9 秒和 32,124 tokens。单轮延迟约增加 90%，tokens 约增加 124%。

第三节经历两次 L256-L301 schema 失败后才改为原子性质块。最终产物只记录恢复阶段 7 次新请求：API latency 407.8 秒、137,938 tokens；前 7 块及两次失败调用的真实成本没有进入最终产物，因此总成本显著更高。三次进程总墙钟时间约 1,550 秒。该现象也暴露出失败运行的 API telemetry 没有落盘。

## 结论

1. 实际改变 chunk 边界确实会改变节点选择与 Claim kind，第四节的两处类型错误得到修复，因此“分块无效”可以排除；
2. 当前人工细拆只在节点指标上呈正向信号，关系依赖、表达式覆盖和成本明显退化，不能称为整体质量提升；
3. 纯例题块调用 Pro 只得到空输出，工程上不值得；后续模板应让第一层跳过已可靠识别的纯例题块，而不是为其单独调用模型；
4. 定理群既不能全部塞进一个大块，也不宜完全原子化。更合理的候选单位是“中心性质 + 紧邻加强形式/推论”，保留局部逻辑上下文；
5. 当前证据不足以模板化。下一轮应先设计一个中等粒度计划，并在第三、四节各重复至少三轮；只有节点 F1 提升能够复现，且 `derived_from`、表达式覆盖和成本不过度恶化，才进入泛化模板实验。
